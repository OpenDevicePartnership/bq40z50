## What this crate is

`bq40z50-rx` (crate name in `Cargo.toml`) is a `#![no_std]`,
platform-agnostic async Rust driver for the Texas Instruments BQ40Z50
family of 1S–4S Li-Ion battery fuel/gas gauges. It targets the
[`embedded-hal`](https://docs.rs/embedded-hal) /
[`embedded-hal-async`](https://docs.rs/embedded-hal-async) traits and
also implements the higher-level
[`embedded-batteries-async`](https://crates.io/crates/embedded-batteries-async)
`SmartBattery` trait on top of the low-level register accessors.

Four silicon revisions are supported, selected by exactly one of the
mutually-exclusive Cargo features `r1`, `r3`, `r4`, `r5`:

- BQ40Z50    (R1, `r1` feature) — sluua43a
- BQ40Z50-R3 (`r3` feature)     — sluubu5a
- BQ40Z50-R4 (`r4` feature)     — sluuch2
- BQ40Z50-R5 (`r5` feature)     — sluucn4b

Key facts:

- **MSRV: Rust `1.85`** (see `Cargo.toml` `rust-version` and
  `.github/workflows/check.yml` `msrv` matrix). Edition: `2024`.
- `#![no_std]` library (`src/lib.rs` sets
  `#![cfg_attr(not(test), no_std)]`).
- `#![deny(unsafe_code)]` and `#![deny(missing_docs)]` are enforced at
  the crate level via `[lints.rust]` in `Cargo.toml`. **Do not add
  `unsafe` code.** The only exception is auto-generated code under
  `src/versions/gen_r*.rs`, which is wrapped with `#[allow(unsafe_code)]`
  in `src/versions/mod.rs`.
- Clippy lint groups `correctness`, `suspicious`, `perf`, `style`,
  `pedantic` are all `deny` per `[lints.clippy]` in `Cargo.toml`.

## Features

From `Cargo.toml`:

| Feature           | Purpose                                                                                  |
|-------------------|------------------------------------------------------------------------------------------|
| `r1`              | Compile against BQ40Z50 (original) register map.                                         |
| `r3`              | Compile against BQ40Z50-R3 register map.                                                 |
| `r4`              | Compile against BQ40Z50-R4 register map.                                                 |
| `r5`              | Compile against BQ40Z50-R5 register map. Used for `docs.rs` (`package.metadata.docs.rs`).|
| `embassy-timeout` | Wrap I2C ops in `embassy_time::with_timeout` using `Config::timeout`.                    |
| `defmt-03`        | Derive `defmt::Format` on public types; pulls in `device-driver/defmt-03`, etc.          |
| `pec-lookup-table`| Forwards to `smbus-pec/lookup-table` for faster PEC at the cost of code size.            |

Exactly one of `r1`/`r3`/`r4`/`r5` is expected to be enabled at a time;
many internal items are `#[cfg(...)]`-gated on combinations of these.
`build.rs` re-emits `cargo:rebuild-if-changed=device_R<rev>.yaml` for
whichever revision feature is active.

## Building and testing

All commands below are taken verbatim from
`.github/workflows/check.yml`, `.github/workflows/nostd.yml`, and
`.github/workflows/device-driver.yml`, and have been re-run locally on
this checkout. Substitute `r5` with `r1`, `r3`, or `r4` to validate
other silicon revisions; CI runs the full `[r1, r3, r4, r5]` matrix.

### Format

`rustfmt.toml` uses the unstable options `group_imports` and
`imports_granularity`, so formatting must be applied/verified with
**nightly** to actually enforce the rules. On stable, `cargo fmt`
prints warnings about those options and ignores them but otherwise
succeeds.

```pwsh
cargo +nightly fmt --check     # CI gate
cargo +nightly fmt             # apply locally
```

### Clippy (per silicon revision)

CI runs clippy for each revision and for `embassy-timeout` combined
with each revision, with these denied lint groups:

```pwsh
cargo clippy --features r5            -- -F clippy::suspicious -F clippy::correctness -F clippy::perf -F clippy::style
cargo clippy --features "embassy-timeout r5" -- -F clippy::suspicious -F clippy::correctness -F clippy::perf -F clippy::style
```

Note: `Cargo.toml` already sets these (plus `pedantic`) to `deny` via
`[lints.clippy]`, so plain `cargo clippy --features r5` is also a valid
local check.

### Build / check

```pwsh
cargo check --features r5                                              # host check (MSRV gate uses this)
cargo check --target thumbv8m.main-none-eabihf --features r5           # no_std target (nostd.yml)
```

Add the target first with:

```pwsh
rustup target add thumbv8m.main-none-eabihf
```

### Tests

There is **no `cargo test` job in CI** today, but the in-tree tests
(generated by the `bq40z50_tests!` macro for each revision) **do** run
and pass locally and should be kept green:

```pwsh
cargo test --features r5
```

Tests use `#[tokio::test]` (single-threaded `tokio` runtime) and
`embedded-hal-mock`'s `eh1::i2c::Mock` to script expected I2C
transactions; see `src/tests.rs`. When `embassy-timeout` is enabled,
the tests include a small `setup()` that constructs a static
`embassy_executor::Executor` so the embassy-time pender symbol resolves.

### Docs

```pwsh
$env:RUSTDOCFLAGS = "--cfg docsrs"
cargo doc --no-deps --features r5
Remove-Item Env:\RUSTDOCFLAGS
```

CI runs this on stable for each of `[r1, r3, r4, r5]` (the workflow
comment notes nightly is currently broken).

### cargo-hack feature powerset

```pwsh
cargo install cargo-hack
cargo hack --feature-powerset clippy --target x86_64-unknown-linux-gnu
```

This is the gate for "features remain additive" — adding a feature
must not make any other combination fail to build or lint.

### cargo-deny

```pwsh
cargo install cargo-deny
cargo deny --manifest-path ./Cargo.toml check --all-features
```

### Regenerating the device-driver code

`src/versions/gen_r*.rs` is produced by
[`device-driver-cli`](https://crates.io/crates/device-driver-cli) from
the corresponding `device_r*.yaml` and committed to the repository so
downstream consumers do not need the codegen toolchain. The
`device-driver` workflow (`.github/workflows/device-driver.yml`)
regenerates each file in CI and **strictly diffs** it against what is
checked in. Any edit to `device_r*.yaml` (or any change in the
device-driver-cli version) requires regenerating and committing the
corresponding `gen_r*.rs`. Reproduce locally exactly as CI does:

```pwsh
cargo install device-driver-cli
device-driver-cli --manifest device_r5.yaml --device-name Device -o src/versions/gen_r5.rs
rustup run nightly rustfmt --edition 2024 src/versions/gen_r5.rs
```

Use **nightly** rustfmt for these files — CI runs `rustup run nightly
rustfmt --edition 2024` before diffing, and the `nightly / fmt` job
will reject files formatted with stable.

### semver

The `cargo-semver-checks` action runs against published versions; any
breaking change in the public API requires a major version bump in
`Cargo.toml` (`version = "..."`).

## Code conventions

- **Formatting (`rustfmt.toml`):**
  - `max_width = 120`
  - `group_imports = "StdExternalCrate"` (nightly-only)
  - `imports_granularity = "Module"` (nightly-only)
- **Lints:** `unsafe_code = "deny"`, `missing_docs = "deny"`, plus the
  full clippy `pedantic` group denied. New public items need rustdoc.
  Internal items inside `mod tests` are exempted by `#![allow(missing_docs)]`
  at the crate root.
- **Edition 2024**, MSRV 1.85. Do not use features stabilized after 1.85.
- **`no_std`:** the crate is `#![cfg_attr(not(test), no_std)]`. Tests
  pull in `std` (for `tokio`, `embedded-hal-mock`, `embassy-executor`'s
  `arch-std`), but library code must not. Use `core::` /
  `embedded_hal_async` / `embedded_batteries_async` rather than `std`.
- **No heap allocations.** There is no `alloc` dependency. All buffers
  are stack arrays sized from `src/consts.rs`
  (`LARGEST_REG_SIZE_BYTES`, `LARGEST_CMD_SIZE_BYTES`,
  `LARGEST_BUF_SIZE_BYTES`, `LARGEST_DF_BLOCK_SIZE_BYTES`). Methods
  that take caller buffers return `BQ40Z50Error::DataTooLarge` when the
  buffer exceeds the supported size.
- **Async everywhere.** The driver is built on
  `embedded_hal_async::i2c::I2c` and
  `embedded_hal_async::delay::DelayNs`. There is no blocking variant.
- **Error type:** `BQ40Z50Error<I2cError>` in `src/error.rs`. Variants
  cover `I2c`, `BatteryStatus`, `Timeout`, `Pec`, `DataTooLarge`. It
  implements `embedded_batteries_async::smart_battery::Error`. When
  `embassy-timeout` is on, it provides `From<embassy_time::TimeoutError>`.
- **Imports:** group as Std / external / crate (handled automatically
  by nightly rustfmt when the unstable options apply).
- **`defmt` integration:** every public type that derives `Debug`
  also has `#[cfg_attr(feature = "defmt-03", derive(defmt::Format))]`
  (see `Config`, `BQ40Z50Error`, etc.). Follow this pattern for any
  new public type.
- **Per-revision modules:** keep behavior shared across revisions in
  `src/common.rs` / `src/interface.rs` / `src/consts.rs`. Revision-
  specific logic lives in `src/versions/r{1,3,4,5}.rs` and re-exports
  the generated `Device` from `gen_r*.rs` via `pub use crate::versions::gen_r<N>::*;`.

## Driver specifics

- **I2C / SMBus:** the device sits at 7-bit address `BQ_ADDR = 0x0B`
  (`src/consts.rs`). The driver speaks SMBus block reads/writes for
  MAC (`0x44`) and ManufacturerBlockAccess style commands. PEC is
  computed via the `smbus-pec` crate; enable the
  `pec-lookup-table` feature to trade flash for runtime speed.
- **Retries and backoff:** I2C operations retry up to
  `Config::max_bus_retries` (default `DEFAULT_BUS_RETRIES = 3`) with a
  `DEFAULT_ERROR_BACKOFF_DELAY_MS = 10` ms delay between attempts,
  using the user-supplied `DelayNs` impl.
- **Optional timeouts:** with `embassy-timeout`, every I2C operation is
  wrapped in `embassy_time::with_timeout(config.timeout, ...)`
  (`DEFAULT_TIMEOUT = 100 ms`). Without the feature, timeouts are not
  enforced and the only error path is whatever the I2C impl returns.
- **Config mutation:** `Bq40z50R<N>::update_config(&mut self, Config)`
  takes `&mut self`, so a config change cannot race with an in-flight
  register transaction (see comment in `src/versions/r5.rs`).
  Preserve that invariant when adding new configuration knobs.
- **Capacity mode tracking:** `CapacityModeState` (mA vs cW) is cached
  in a `core::cell::Cell` on the revision wrapper struct and updated
  whenever `BatteryMode` is read. New code that affects `BatteryMode`
  should call `set_capacity_mode_state` to keep this cache coherent.
- **MAC special cases:** Security keys (`0x0035`), Auth key (`0x0037`),
  Mfg Info (`0x70`), and `ChargingVoltageOverride` (`0x00B0`, not on
  R1) are handled as dedicated methods rather than via the generated
  field-set API. Follow that pattern for any MAC command that needs
  bespoke length handling.

## Commit & PR conventions

From `CONTRIBUTING.md` and the existing `git log`:

- **One logical change per commit.** Each commit must build cleanly
  with no warnings (`CONTRIBUTING.md`: "Each commit builds successfully
  without warning").
- **Squash typo / formatting fix-ups** into the original commit before
  pushing for review.
- **PRs:** open as a **draft first**, make sure all CI checks
  (`check`, `no-std`, `device-driver-pregen-check`) pass on the draft,
  then mark as ready for review.
- **Squash-on-merge is disabled** — the rebased/clean history you push
  is what lands on `main`.
- **Subject style:** observed in `git log --pretty=%s`, recent commits
  use short imperative subjects with a `(#NN)` PR suffix added by the
  merge, e.g.:
  - `Bump device-driver to 1.0.9 (#56)`
  - `Allow changing driver config on the fly (#55)`
  - `Add PEC support to all reads and writes (#44)`
  Do not invent conventional-commit prefixes (`feat:` / `fix:` /
  `chore:`) — they are not used here. Write the subject as a short
  capitalized imperative sentence, no trailing period.
- **Regressions:** when reporting one, run `git bisect` first
  (`CONTRIBUTING.md`).

## What not to do

- ❌ Do not add `unsafe` code outside `src/versions/gen_*.rs`. The
  crate denies `unsafe_code`.
- ❌ Do not hand-edit `src/versions/gen_r*.rs`. They are regenerated
  from `device_r*.yaml` and diffed strictly in CI. Edit the YAML and
  regenerate (see "Regenerating the device-driver code" above).
- ❌ Do not add a `std` dependency to the library or to any
  non-`dev-dependencies` section of `Cargo.toml`.
- ❌ Do not introduce heap allocation (`alloc`, `Vec`, `String`,
  `Box`, …) in library code. Use stack arrays sized from
  `src/consts.rs`.
- ❌ Do not enable more than one of `r1` / `r3` / `r4` / `r5` at the
  same time; the `#[cfg]` gates assume exactly one is active.
- ❌ Do not bump MSRV (`rust-version` in `Cargo.toml` and `msrv`
  matrix in `.github/workflows/check.yml`) without coordinating with
  maintainers — both must move together.
- ❌ Do not introduce blocking I2C or `Delay` traits; the public API
  is async-only.
- ❌ Do not format generated files with stable rustfmt; CI uses
  `rustup run nightly rustfmt --edition 2024`.
- ❌ Do not force-push to shared branches or rewrite history on
  branches that already have review comments.
